## Цели работы

- Понять принципы иерархического проектирования **Multi-Area OSPF**.
- Настроить OSPF-сеть с backbone и дополнительными областями.
- Проверять соседство, таблицу маршрутизации и типы **LSA**.
- Отработать поиск неисправностей на разных уровнях модели OSI.
- Восстанавливать связность и подтверждать результат контрольными проверками.

## Топология

![Топология Multi-Area OSPF в GNS3](https://github.com/user-attachments/assets/55b171f3-383b-4f4f-8fc3-22367a9e13d6)

Стенд включает восемь маршрутизаторов **R1–R8**, коммутатор уровня доступа и конечные узлы **PC1–PC5**. Такая схема позволяет проверять распространение маршрутов между областями и локализовать неисправность последовательно: от клиента до OSPF-соседства.

## Практические задачи

1. Настроить IP-адресацию и включить необходимые интерфейсы.
2. Назначить интерфейсы в соответствующие OSPF-области.
3. Проверить установление соседств и обмен маршрутной информацией.
4. Изучить содержимое LSDB и маршруты, полученные из других областей.
5. Внести неисправность, локализовать её и восстановить связность.
6. Задокументировать команды диагностики, причину и результат исправления.

## Порядок проверки

| Команда | Что анализировать |
|---|---|
| `show ip interface brief` | Состояние и IP-адреса интерфейсов |
| `show ip ospf interface brief` | Участие интерфейсов в OSPF, области и состояние |
| `show ip ospf neighbor` | Наличие соседей, состояние `FULL`, Router ID и Dead Time |
| `show ip route ospf` | OSPF-маршруты, административная дистанция и next hop |
| `show ip ospf database` | LSA, Advertising Router и распространение информации по областям |
| `ping` / `traceroute` | Доступность конечного узла и участок потери связности |

## Сценарии неисправностей

### 1. Пропал канал между R2 и R4

**Симптом:** пропала связь с `PC 10.0.10.2`.  
**Метод:** трассировка → проверка OSPF-соседства → проверка состояния интерфейса.  
**Причина:** интерфейс, ведущий к соседу, administratively down.  
**Результат:** после включения интерфейса восстановлены соседство и доступность ПК.

### 2. Нет OSPF-соседства между R2 и R4

**Симптом:** от R2 недоступен `PC 10.0.20.3`, соседство с R4 отсутствует.  
**Метод:** проверка соседства и OSPF-параметров на обоих маршрутизаторах.  
**Причина:** на R4 отсутствует необходимая OSPF-конфигурация для соответствующей зоны.  
**Результат:** после добавления конфигурации соседство восстановлено.

## Запуск

1. Установите GNS3 и совместимый образ Cisco IOS.
2. Откройте `ospf_dhcp_nat_vlan_ssh.gns3` и при необходимости обновите пути к образам.
3. Запустите узлы и примените конфигурации из `Router_Config.md`.
4. Выполните базовые проверки из таблицы выше.
5. Для практики повторите сценарии неисправностей, не открывая готовое решение до самостоятельной локализации проблемы.
